Part 1

Understand before you click

Six short pages that make every later step easier.

1.1 Portal, CLI or Bicep? A quick correction

You may have heard that CloudMart "uses the Azure CLI to create its resources". That is almost right. Here is the precise picture:

  • CloudMart's resources are described in Bicep files: infra/main.bicep plus 27 modules in infra/modules/. Bicep is a blueprint. It says what should exist, not the clicks or commands to get there.
  • The Azure CLI is the courier. az deployment sub what-if previews the blueprint and az deployment sub create hands it to Azure, which builds everything in the right order. The CLI does not create the resources one command at a time.
  • The CLI is used directly only for hands-on jobs: signing in (az login), uploading code (az webapp deploy), building images (az acr build) and lab exercises.
  • From phase 8, an Azure Pipeline runs the same commands for you whenever code is pushed.
Azure PortalAzure CLIBicep
What it isThe website at portal.azure.comA command-line tool, azText files that describe resources
Best forLearning, exploring, checking, one-off fixesScripts, quick tasks, launching BicepWhole environments: repeatable, reviewed in Git
In CloudMartYou, while learning (this guide)az login, az deployment sub create, az webapp deployinfra/: the real source of truth
The golden rule: learn in the portal, build with Bicep

If you change a Bicep-managed resource by clicking, the next Bicep deployment may quietly put it back. This is called drift. So in this guide you build a separate practice copy in its own resource group, rg-cloudmart-lab, and delete it at the end. Your real Bicep environment, rg-cloudmart-dev, never sees your clicks.

1.2 Azure in five ideas

Almost everything in Azure fits into one picture. Learn these five words and the portal starts to make sense.

Three more facts that save beginners hours

  • Some names are global. A key vault, storage account or web app name becomes a web address (for example kv-cloudmart-xy123.vault.azure.net), so nobody else in the world can be using it. That is why this guide adds a personal suffix, xy123. Replace it with your initials and three random digits, the same everywhere.
  • Resources live in one region, chosen when you create them. Keep everything in the same region (this guide uses East US 2, like CloudMart's Bicep) so the parts talk to each other quickly and cheaply.
  • Tags are sticky notes (name = value) you put on resources, for example environment = lab. Cost reports and policies can use them.
Beginner note: "resource provider"

Each kind of resource is run by a resource provider, such as Microsoft.KeyVault or Microsoft.Web. A provider must be registered (switched on) for your subscription before you can use it. Azure usually does this for you; Step 1 shows what to do when it doesn't.

1.3 Two kinds of permission

This is the idea that surprises almost every beginner, and you will meet it in Steps 7 and 8. Azure has two separate sets of locks:

Managed identities: an ID badge for an app

Apps need data roles too. Instead of giving an app a password or key (which can leak), Azure gives it a managed identity: a badge that Microsoft Entra ID recognises. The app shows the badge, gets a short-lived token, and the vault checks whether that badge has a role. CloudMart uses no passwords or keys at all, only identities.

System-assigned or user-assigned?

A system-assigned identity is born and dies with one app. A user-assigned identity is its own resource: you create it first, give it roles, then attach it to any app. CloudMart uses user-assigned identities (infra/modules/identity.bicep), so you will too.

1.4 Money: avoiding a surprise bill

Azure charges in three main ways: per hour for things that are always running (like an App Service plan), per use for serverless things (Functions, storage transactions) and per gigabyte for stored data and logs. Watch out: a budget is an alarm, not a limit

An Azure budget emails you when spending crosses a line. It does not stop or delete anything. Only deleting resources stops the charges. Cost data also updates a few times a day, not instantly.

Free account

A new Azure free account usually comes with some credit for the first 30 days plus always-free amounts of popular services. Check the current offer at azure.microsoft.com/free. At work, ask your Azure administrator for a sandbox subscription instead of using a production one.

1.5 A tour of the Azure Portal

Open https://portal.azure.com and sign in. The home page looks roughly like this:

  • 1Portal menu: Home, Dashboard, All services, Favorites.
  • 2Search bar: the fastest way anywhere. Type a service ("key vaults") or a resource's name.
  • 3Cloud Shell (>_): a terminal in your browser with the Azure CLI and Bicep already installed.
  • 4Notifications (bell): deployment progress appears here.
  • 5Settings, help, account: switch directory (tenant), theme, language; see who you are signed in as.
  • 6Create a resource: the Marketplace of everything you can create.
  • 7Recent resources: jump back to what you were working on.

Every resource page has the same skeleton

  • ALeft menu. Every resource has Overview, Activity log, Access control (IAM), Tags and, under Settings, Locks.
  • BCommand bar: actions for this resource, such as Delete or Restart.
  • CEssentials: the key facts (group, region, subscription, address). You will copy values from here.

1.6 The pattern every "Create" follows

Creating anything in the portal, from a resource group to a database, goes through the same wizard. Once you know the pattern, every step in Part 2 feels familiar.

1Find itSearch the service, e.g. "Key vaults".
2+ CreateOpens the create wizard.
3Basics tabSubscription, resource group, name, region, size.
4Other tabsNetworking, security, monitoring, tags.
5Review + createAzure validates your choices.
6CreateSends the request to Resource Manager.
7Deployment in progressWatch it under the bell.
8Go to resourceFinish the settings there.
  • 1Tabs run left to right. You can jump between them; most have sensible defaults.
  • 2Resource group: always pick rg-cloudmart-lab in this guide.
  • 3Name: a green tick means it is valid and free. A red asterisk (*) means required.
  • 4Review + create runs validation. You must then click Create on the next page.
Why the review page matters

The Review + create page usually has a link such as Download a template for automation (or View automation template). It shows the exact template the portal is about to send, which is the same kind of file that CloudMart's Bicep produces. Peek at it once; it makes Part 4 obvious.

How to tell a create worked

The page changes to "Your deployment is complete" with a green tick, and the bell shows "Deployment succeeded". Click Go to resource. If it fails, the page shows an error code; look it up in the Troubleshooting table at the back.

Two managed identities: ID badges for the apps

TIME5 minCOSTfreeBICEPinfra/modules/identity.bicep
Why

Each app gets its own badge, so each can be given only the access it needs (the idea of least privilege). Creating the badges before the apps lets you grant access in Steps 7 and 8 before the apps even exist.

Click pathSearch›Managed Identities›+ Create

Client ID or Object (principal) ID?

An identity shows two IDs. The Client ID is what an app's settings use (AZURE_CLIENT_ID). The Object (principal) ID is what role assignments use behind the scenes. In the portal you pick identities by name, so you only need to note the Client ID.

What is a SAS?

A shared access signature is a link that grants narrow, temporary access, such as "upload this one file in the next 10 minutes". The API signs one with its identity so a shopper's browser can upload an image directly, without ever holding a key. This is called the valet key pattern.

4.5 · Now do it the real way, with Bicep

You have built the foundation by hand in about two hours. CloudMart's Bicep builds the same thing, plus the pieces later phases need, in about five minutes, and can rebuild it identically any time.

  1. Clean up the lab first (Part 5), so you don't pay twice and don't confuse the two copies.
  2. Find your IDs in the portal: search Microsoft Entra ID › Users › select yourself. Copy your Object ID and User principal name.
  3. Fill in infra/main.bicepparam: deployerPrincipalId = your Object ID, deployerPrincipalName = your user principal name, ownerEmail = where alerts go.
  4. Preview, then deploy from a terminal (your laptop, or Cloud Shell in the portal after cloning the repository there): 
    az deployment sub what-if -l eastus2 -f infra/main.bicep -p infra/main.bicepparam
az deployment sub create  -l eastus2 -f infra/main.bicep -p infra/main.bicepparam
  5. Watch it in the portal while it runs: Subscriptions › your subscription › Settings › Deployments › the newest deployment. Each module (governance, monitoring, identity, key-vault, storage …) appears as it starts and finishes.
  6. Explore the result: open rg-cloudmart-dev. Every resource you met in Part 2 is there, with the same settings. Use your new portal skills to inspect it, but change things through the Bicep files, not by clicking.
Watch out: false does not delete

Setting a switch back to false and running az deployment sub create stops managing that resource, but does not delete it. Delete it yourself, delete the resource group, or use a deployment stack (learning path, phase 8), which really removes what you take out of the template.

The habit to keep for every phase

The learning path's loop is: click it once in the portal to see the options, script it once with the CLI to learn the model, then read the Bicep that does it. This guide was the "click it" half for phase 1.

Where Azure tells you more

Failed deployments: resource group › Deployments › the failed one › Error details. Anything that changed: Activity log. A resource misbehaving: its Diagnose and solve problems page, which often names the cause.

Glossary

Action group: a list of people and channels (email, SMS, webhook) an alert notifies.

App Service plan: the rented machine(s) your web apps run on; you pay for it per hour.

ARM (Azure Resource Manager): the service behind the portal, CLI and Bicep that checks and carries out every request.

Bicep: Microsoft's language for describing Azure resources in files. Compiles to ARM templates (JSON).

Blade: a page in the portal, such as a resource's Overview.

Blob: a file stored in a storage account container.

Cloud Shell: a terminal in the portal with the Azure CLI and Bicep preinstalled.

Control plane: managing a resource (create, configure, delete). Roles: Owner, Contributor, Reader.

CORS: a browser rule; a site must say which other websites may call it.

Data plane: using what is inside a resource (secrets, files, messages). Needs data roles.

Deployment: a record of a request to create or update resources, from a wizard, CLI or Bicep.

Drift: when a resource is changed by hand and no longer matches its Bicep.

Entra ID (Microsoft Entra ID): Azure's directory of users, groups and app identities. Formerly Azure Active Directory.

Flex Consumption: the serverless plan for Azure Functions: pay per use, scale to zero.

Idempotent: running it twice gives the same result as running it once. Bicep deployments are.

KQL (Kusto Query Language): the query language for Log Analytics and Application Insights.

Lock: stops a resource being deleted (Delete) or changed (Read-only), even by Owners.

Managed identity: an identity Azure manages for an app, so the app needs no password or key.

Policy (Azure Policy): rules about what may exist, e.g. "only in East US 2". Effects include Deny, Audit and Modify.

RBAC (role-based access control): giving a role to someone (or something) at a scope.

Region: a set of datacentres in one geography, e.g. East US 2.

Resource: one thing you create: a vault, an app, a storage account.

Resource group: a folder of resources that share a lifecycle.

Resource provider: the Azure service that runs a resource type, e.g. Microsoft.KeyVault.

Role assignment: role + who + scope, e.g. "Key Vault Secrets User for id-…-api on this vault".

SAS (shared access signature): a link that grants narrow, temporary access to storage.

Scope: where a role, policy or lock applies: management group, subscription, resource group or resource.

SKU / pricing tier: the size or edition of a resource, e.g. B1, Standard, Free.

Soft delete: deleted things are kept for a while so they can be recovered.

Subscription: the billing and access boundary that resources belong to.

Tag: a name = value label on a resource.

Tenant: your organisation's instance of Microsoft Entra ID.

What-if: a preview of what a Bicep deployment would change, before it changes anything.
